MIPS 的指令格式

R 格式
op rs rt rd shamt funct
6bit 5bit 5bit 5bit 5bit 6bit
I 格式
op rs rt immediate
6bit 5bit 5bit 16bit
J 格式
op address
6bit 26bit
三种格式一览 R 格式在寄存器之间做运算（op + funct 共同决定操作）； I 格式额外带 16bit 立即数，用于常数与访存； J 格式只保留 6bit 的 op 与 26bit 的 address，用于跳转。 三种格式都以开头的 6bit op 开头，因此指令长度恒为 32 位。

R 格式

op rs rt rd shamt funct
6bit 5bit 5bit 5bit 5bit 6bit
字段 位宽 含义
op 6bit 指令操作码（opcode：操作码）
rs 5bit 第 1 源操作数（source operand）
rt 5bit 第 2 源操作数（source operand）
rd 5bit 目的操作数（destination operand）
shamt 5bit 移位量（shift amount）
funct 6bit 功能码（function code）
说明 R 格式是「寄存器—寄存器」型运算指令的通用格式。op 与 funct 组合起来才能唯一确定是哪一条指令；shamt 只在移位指令中使用，其它指令中为 0。

立即数操作数

add  a, b, c    # a = b+c
add  a, b, 4    # a = b+4 ???
addi a, b, 4    # a = b+4
为什么不行？ add 是 R 格式指令，三个操作数都必须是寄存器； 常数 4 无法放进 R 格式的字段里书写。
写作 含义 可否
add a, b, c a = b + c 可以（三个操作数都是寄存器）
add a, b, 4 a = b + 4 不可以（add 不能直接写常数）
addi a, b, 4 a = b + 4 可以（用 addi 指令）
结论 要进行常数的加法时，使用 addi 指令。
addi：add immediate（立即数加法）　│　 立即数（immediate）：直接写在运算所用操作数中的值。

I 格式

op rs rt immediate
6bit 5bit 5bit 16bit
字段 位宽 含义
op 6bit 指令操作码（opcode：操作码）
rs 5bit 第 1 源操作数（source operand）
rt 5bit 第 2 源操作数（source operand）
immediate 16bit 立即数操作数
说明 I 格式用 16bit 的立即数字段取代了 R 格式中的 rd、shamt、funct， 因此可以处理常数；但立即数只有 16 位宽，并且该字段在不同指令中还可以表示偏移量或地址（见后续寻址模式）。

立即数操作数（R 格式与 I 格式的对比）

R 格式：在 32 个寄存器中指定 1 个 → 5bit
op rs rt rd shamt funct
6bit 5bit 5bit 5bit 5bit 6bit
32 个寄存器中指定 1 个 → 5bit 不使用 
add a, b, c    # a = b+c
I 格式：16bit → -32768 ～ 32767
op rs rt immediate
6bit 5bit 5bit 16bit
寄存器编号 16bit → -32768 ～ 32767 
addi a, b, 4    # a = b+4
lw   $s1, 8($s2) # 8 is immediate
sw   $s1, 8($s2) # 8 is immediate
说明 R 格式只能处理寄存器中的值；I 格式则额外带有一块 16bit 的立即数字段， 所以既可以写常数（addi），也可以写访存偏移量（lw、sw）。
原文对照：32個のレジスタのうち1つを示す→5bit ／ 16bit → -32768～32767
8 / 24

无符号立即数（unsigned immediate）

addi  a, b, -4   # a = b-4
addiu a, b, 4    # a = b+4
  • addiu 指令进行无符号整数（unsigned integer）的加法。
  • addi 与 addiu 的区别只在于把 16 位立即数解释为有符号还是无符号。
注意 两者都不会因立即数相加而产生溢出异常；需要检测溢出时要使用 add 系列指令。
指令 可处理的常数范围 说明
addi -32768 ～ 32767 把 16bit 立即数视为带符号整数
addiu 0 ～ 65535 把 16bit 立即数视为无符号整数
小结：立即数字段永远是 16bit，能表示的范围由指令对它的解释方式决定 —— 带符号解释得到 −32768～32767，无符号解释得到 0～65535。

确认问题

(1) 以下各指令分别属于 R 格式还是 I 格式？
add　addi　addiu　lw　sw
(2) I 格式中的「I」表示什么？
(3) R 格式的指令中，存在几个操作数？
(4) I 格式的指令所能保存的立即数位宽是多少？
解题提示
  • 先看指令有没有立即数或偏移量：有则是 I 格式，只有寄存器之间的运算则是 R 格式。
  • lw／sw 虽然名字里没有「i」，但它们需要 16bit 的偏移量，因此也是 I 格式。
  • R 格式的 32 位被 6 个字段瓜分：op、rs、rt、rd、shamt、funct。

确认问题：解答与小结

题号 参考答案 理由
(1) R 格式：add
I 格式：addi、addiu、lw、sw		 凡是需要 16bit 立即数／偏移量的指令都是 I 格式；add 的三个操作数全是寄存器，故为 R 格式。
(2) Immediate（立即数） I 格式的特征字段就是 16bit 的 immediate，所以 I 取自 Immediate。
(3) 3 个 由 rs（第 1 源）、rt（第 2 源）、rd（目的）三个操作数构成，另加 op、shamt、funct 三个控制字段。
(4) 16bit 立即数字段固定为 16bit；带符号解释时范围为 −32768～32767，无符号解释时为 0～65535。
本节小结 指令格式决定了「一条 32 位指令里，哪些位用来表示什么」。R 格式面向寄存器间运算， I 格式面向立即数与访存，J 格式面向跳转。记住字段的排列与宽度， 就能把汇编指令翻译成机器语言（二进制），也能反过来从二进制还原出指令。

指令格式的判别

问题 计算机是如何区分指令的格式的？
  • 只要读取每条指令开头的 6 位（opcode），就能知道格式。
  • 例如：为 0 则是 R 格式，为 3510（lw）则是 I 格式。
开头的 6 位决定一切
op（前 6 位） rs rt rd shamt funct
op（前 6 位） rs rt immediate
op（前 6 位） address
三种格式的前 6 位都放在同一位置，所以解码器只需先看这 6 位即可分流。
开头的 6 位（opcode） 判别的格式 例子
0 R 格式 add、sub、sll、srl
3510 I 格式 lw
2 或 3 J 格式 j、jal

移位运算

sll $s0, $s1, 4
srl $s0, $s1, 4
  • sll $s0, $s1, 4 …把 $s1 的值逻辑左移 4 位后存入 $s0（shift left logical）
  • srl $s0, $s1, 4 …把 $s1 的值逻辑右移 4 位后存入 $s0（shift right logical）
R 格式
op rs rt rd shamt funct
6bit 5bit 5bit 5bit 5bit 6bit
书写形式 op funct
sll (rd), (rt), (shamt) 0 0
srl (rd), (rt), (shamt) 0 2
移位指令是 R 格式中唯一真正使用 shamt 的一类；移位量只有 5 位，因此一次最多移动 31 位。

与数组使用对应的汇编代码

（例）
a[300] = b + a[200]
寄存器分配
a : $t1
b : $s1
汇编代码
lw  $t0, 800($t1)     # $t0 = a[200]（200×4 = 800）
add $t0, $s1, $t0     # $t0 = b + a[200]
sw  $t0, 1200($t1)    # a[300] = $t0（300×4 = 1200）
关键 存储器地址的偏移量是数组下标（元素个数）的 4 倍。因为 1 个 int 占 4 字节， 所以第 n 个元素的字节偏移是 n × 4。
为什么用「基址 + 偏移」
  • $t1 中保存的是数组的首地址，作为基址寄存器。
  • 偏移量以常数形式写在括号之前（800($t1)），这正是 I 格式 16bit 立即数字段的用武之地。

与数组使用对应的汇编代码（下标是变量）

（例）
a[i] = b + a[i]
寄存器分配
a : $t1
b : $s1
i : $s2
汇编代码
sll $t2, $s2, 2       # $t2 = i×4（用移位运算计算 4 倍）
add $t2, $t2, $t1     # $t2 = &a[i]（首地址 + 偏移）
lw  $t0, 0($t2)       # $t0 = a[i]
add $t0, $s1, $t0     # $t0 = b + a[i]
sw  $t0, 0($t2)       # a[i] = $t0
要点 使用移位运算来计算 4 倍：sll $t2, $s2, 2 等价于 $t2 = $s2 × 4， 比乘法指令更快；随后把「首地址 $t1」与「偏移 $t2」相加，得到元素 a[i] 的实际地址。

确认问题：解答与小结

空栏 参考答案 说明
(1) sll 用逻辑左移 2 位求出 i×4，即元素 a[i] 相对首地址的字节偏移。
(2) add 首地址 $t1 与偏移 $t2 相加，把 a[i] 的实际地址存入 $t2。
(3) lw 从该地址装入数据：$t0 = a[i]。
(4) sub 做减法：$t0 = $s1 - $t0，即 b - a[i]。
(5) 200 a[50] 的偏移是 50 × 4 = 200。
(6) $t1 基址寄存器（数组首地址）。完整写法：sw $t0, 200($t1)。
小结 数组访问的固定套路：下标 ×4 → 加首地址 → 访存。乘法用 sll 代替， 地址相加用 add，读写用 lw／sw，常数下标则直接写进偏移量。
