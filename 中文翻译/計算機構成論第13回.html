吞吐量与响应时间

  • 吞吐量（日文：スループット / throughput）
    • 单位时间内完成的工作量。
  • 响应时间（日文：応答時間 / response time）
    • 计算机完成一项任务所需的时间。
      • 包含磁盘访问、存储器访问、输入输出操作、OS 的开销、CPU 执行时间等。
问题 在以下情况下，吞吐量与响应时间中的哪一个（或者两者同时）会改善？
1.把处理器更换为更高速的处理器。
2.在把任务分担给多个处理器来处理的系统中，增加处理器。

执行时间的构成

关于某台计算机 X，以下关系成立
性能X = 1 执行时间X
等价关系 执行时间减半 ⇔ 性能变为 2 倍。
※ 这里的「性能」指的是时间意义上的性能。
  • 执行时间 ＝ 响应时间 ＝ 经过时间（日文：経過時間 / elapsed time）
    • 包含磁盘访问、存储器访问、输入输出操作、CPU 执行时间等。
  • CPU（执行）时间 ＝ 系统 CPU 时间 ＋ 用户 CPU 时间
    • 用户 CPU 时间：CPU 针对某个用户程序实际进行处理的时间。
    • 系统 CPU 时间：OS 的开销所占用的作业时间。

指令执行所需的时钟周期数

  • 复杂的指令（乘法、除法等）需要多个时钟周期。
  • 使用流水线处理等时，所需的 CPU 时钟周期数会随情况而变化。
CPI（clock cycles per instruction）
  • 每指令平均时钟周期数。
  • 通常取整个程序的平均值。
关系式 某个程序的执行所需的 CPU 时钟周期数 ＝ 指令数 × CPI

MIPS

  • 并非指 MIPS architecture（MIPS 体系结构）。
  • million instructions per second（每秒百万条指令）。
MIPS ＝ 执行的指令数 执行时间 × 106
优点
  • 与单位时间内执行的指令数成正比，因此直观易懂。
缺点
  • 没有考虑指令的具体内容。
    • → 无法在不同指令集之间进行比较。
  • 即使是同一台计算机，程序不同，执行的指令数也会不同。

基准测试程序

  • 哪一个更好？
    • 计算机 A：程序 1 用 1 秒，程序 2 用 1000 秒。
    • 计算机 B：程序 1 用 10 秒，程序 2 用 100 秒。
  • 用许多程序来考察并取平均即可。
    • → 那么应当针对什么样的程序来评价？
  • 基准测试程序（日文：ベンチマーク / benchmark）： 为评价计算机性能而选定的一组程序。
SPEC（Standard Performance Evaluation Corporation）
  • 制定基准测试程序的组织。
  • 把实际常用的应用程序采纳为基准测试程序。
  • 最新版为 SPEC CPU2017。
  • SPEC ratio（SPEC 比值）
    • 基准处理器上的执行时间 ／ 被测对象上的执行时间 ＝ 相当于基准的多少倍快。
    • 在两台计算机之间进行比较时，取 SPEC ratio 的几何平均（日文：幾何平均）。

阿姆达尔定律（Amdahl's law）

  • 某项改进所带来的性能提升，会被使用该改进功能的占比所制约。
改进后的执行时间 ＝ 受改进影响的执行时间 改进倍数 ＋ 不受改进影响的
执行时间
  • 例：90% 为 CPU 处理、10% 为 I/O 处理。
    • 使用快 10 倍的 CPU 时，整体时间会怎样？
    • 如果是快 100 倍呢？
    • 如果是无限快的 CPU 呢？
说明 不受改进影响的那部分（这里是 I/O 处理的 10%）在改进后完全不会变快，因此无论把 CPU 加速多少倍，整体时间都无法低于这部分所占的比例——这就是阿姆达尔定律的要点。

摩尔定律（Moore's law）

图：1980 年代中期以后处理器性能的提升（原书 图 1.17 重绘为中文示意图）。纵轴为以 VAX-11/780 为基准的性能（对数刻度），横轴为年份；图中按年代标出三个增长阶段——约 25%/年（早期 RISC、VAX 时代）、52%/年（1980 年代后期～2000 年代初）、22%/年（2000 年代中期以后），并给出各阶段的代表机型。
  • 每 1.5 年，单位面积的晶体管数变为 2 倍。
  • → 带来容量与性能的提升、以及价格的下降。
